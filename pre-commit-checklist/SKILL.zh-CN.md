# 提交前检查清单

## 概述

提交或标记任务完成之前，先运行下面的检查。任何一项不过关的变更都不算完成。

## 何时使用

- 创建提交之前
- 声明任务/功能完成之前
- 完成一次实现之后

## 检查清单

- [ ] **构建通过** —— 构建命令以 0 退出（如 `npm run build`）
- [ ] **测试通过** —— 单元测试与 e2e 测试全部通过（`npm test`）
- [ ] **Lint 通过** —— lint 无报错（`npm run lint`）
- [ ] **无调试残留** —— 没有遗留的 `console.log`、`debugger` 或注释掉的代码
- [ ] **无密钥泄露** —— diff 中不包含 API 密钥、token 或 `.env` 值
- [ ] **只暂存预期文件** —— 没有多余的/生成的文件
- [ ] **提交信息遵循格式** —— 参见 `commit-conventions` skill（Angular/Conventional Commits）

有任何一项未勾选，先修复再提交。验证靠证据而非断言 —— 要实际运行命令并确认输出。

## 常见错误

- 说"我觉得应该能构建"却从不实际运行
- 把调试日志"暂时"留着
- 提交了 `.env` 或硬编码的密钥
